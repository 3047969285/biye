**作者：** wangchangzhen

> 本文档与当前代码库一致，用于撰写「需求分析—总体设计—详细设计与实现」等章节；附录给出 **SQL 脚本使用顺序**（见项目 `sql/README.md`）。

---

## 1 引言

本系统在传统 **若依（RuoYi-Vue）** 权限与业务框架基础上，面向 **电力设备运维管理** 场景扩展：设备与多维数据管理、运行状态与 **规则评估 / 告警** 联动、基于 **Spring AI** 与大语言模型的智能问答与 **检索增强（RAG）**、**运维表单** 编排与站内消息推送，并集成 **风力发电功率预测**（Java 与本地 Python / 深度学习模型 HTTP 协同）。下文从 **功能划分、实现位置、数据与接口** 三方面归纳。

---

## 2 系统目标与总体架构

### 2.1 建设目标

- 统一管理电网相关 **设备主数据** 及运行、环境、告警、故障、维护等多类业务数据。
- 在 **运行状态** 变更时自动执行 **规则评估**：命中规则则写入 **告警**，并综合结果回写 **建议运行状态**、**需维护** 等字段。
- 提供 **AI 对话、知识库问答、数据库自然语言查询、运维表单生成** 等能力。
- 提供 **风力发电功率预测** 的配置、按设备数据隔离、Excel/内联序列、结果可视化与 **中文运维总结**。
- 提供 **站内消息中心**：运维表单待处理、待维护设备提醒；**按用户 + 消息类型 + 业务主键去重**，避免重复推送。

### 2.2 总体架构

**前后端分离**：前端 **Vue 2 + Element UI**（`ruoyi-ui`）；后端 **Spring Boot 3** 多模块：

| 模块 | 职责 |
|------|------|
| `ruoyi-admin` | Web 入口，聚合 Controller（设备、风力预测、系统参数等） |
| `ruoyi-system` | 领域实体、Mapper、业务服务（设备、规则、告警、站内消息、风力预测绑定等） |
| `ruoyi-framework` | 安全、日志、分页、Redis 等 |
| `spring-ai` | Spring AI 调用（通义等）、RAG、运维表单编排、与 `Eq*` 数据访问协作 |
| `ruoyi-quartz` | 定时任务（如「检查报警」聚合需维护设备并触发消息同步） |

数据层：**MySQL + MyBatis**；安全：**Spring Security + JWT**，接口级 **`@PreAuthorize`**。

## 3 功能模块设计与实现

### 3.1 设备与运维数据管理

**功能**：设备台账及关联数据的增删改查、导出与统计；覆盖运行状态、参数、告警、故障、维护及机械/运行/技术/电气/经济/环境/气候等维度子表。

**实现要点**

- 分层：**Controller → Service → Mapper → XML**；设备相关接口多在 **`/equipment/*`**，权限前缀 `equipment:*`。
- 设备删除在业务层 **级联删除** 子表，保证引用一致。
- 支持单台/批量状态变更、编号唯一校验；首页/看板聚合接口支撑可视化。

**论文可写点**：多表业务模型；级联删除事务与顺序。

---

### 3.2 设备规则与运行状态联动

**功能**：按设备配置监测规则（阈值、区间等）；**运行状态** 新增或更新后，根据测点快照 **匹配规则**，产生 **告警** 并合并结果 **回写状态**（建议状态、需维护标志等）。

**实现要点**

- **规则触发**（`IEqDeviceRuleTriggerService`）：解析规则条件与快照值比对；同规则未处理告警 **去重**。
- **规则评估编排**（`IEqDeviceRuleEvaluationService`）：聚合触发结果后 **一次性回写** 状态，减少多次更新。
- 状态写库成功后由 **设备运行状态 Service** 触发评估链路。

**论文可写点**：轻量规则引擎与写库解耦；`RuleTriggerResult` 一类 DTO 封装。

---

### 3.3 智能问答与知识增强（RAG）

**功能**：运维领域对话；文档向量化与检索片段拼入 Prompt；SSE **流式输出**；结构化运维表单 JSON 输出（可与 3.5 设备驱动表单互补）。

**实现要点**

- **Spring AI** `ChatClient`；可配置 **阿里云通义（DashScope）**。
- RAG：**Embedding + VectorStore**（如 **SimpleVectorStore** 文件持久化）；文档切分后入库。
- 路径示例：`/springai`、`/springai/rag`；对话落 **`ai_chat_record`**，区分 basic / rag / db 等类型。

**论文可写点**：索引—检索—生成流水线；向量存储与持久化；SSE 协议。

---

### 3.4 数据库自然语言查询（Text-to-SQL）

**功能**：自然语言生成 **SELECT**，服务端 **只读校验** 后执行，结果可附 **中文摘要**（模型 + 规则降级）。

**实现要点**

- 接口如 **`/springai/db`**：`/ask`、`/query`、`/tables`、`/context` 等；**JdbcTemplate** 执行 SQL。
- 对 `eq_*`、`ai_maintenance_form` 等提供元数据上下文，降低列名幻觉。

**论文可写点**：只读安全边界；摘要双通道设计。

---

### 3.5 运维表单业务编排

**功能**

- 从 **需维护设备列表** 聚合：状态、**待处理故障**、**未恢复告警** 等；可选 **AI 一句话摘要**（`aiSummary` 开关，首屏可关以提速）。
- **单台 / 批量** 生成运维表单并可选入库；表单 **分页、详情、修改、删除**。
- **批量生成** 成功后：右侧展示 **可折叠列表**，按设备切换 **当前表单**（修复多成功条仅 `success===1` 时才有展示的空白问题）。
- **问题描述**（列表列）：仅展示 **待处理故障 + 未恢复告警** 合并文案；展示层去掉英文字母，避免混入英文描述。
- **故障描述** 字段：服务端用 **大模型对故障与告警要点做中文总结**（无条数统计类废话、可换行）；失败则规则压缩。

**实现要点**

- 接口前缀 **`/ai/maintenance-form`**，`MaintenanceFormService` 与 `EqFaultRecord`、`EqAlertRecord`、`EqDeviceStatus` 等协作。
- 入库成功可调用 **`ISysUserMessageService.notifyMaintenanceFormPending`** 推送站内信（见 3.8）。

**论文可写点**：多源数据融合 Prompt；`aiSummary` 与性能成本；批量结果与 UI 状态一致性。

---

### 3.6 风力发电功率预测

**功能**

- 展示 Python 服务可达性与 **最近一次预测曲线**；**全局立即预测** 与 **按设备预测**。
- **设备绑定表 `eq_wind_forecast_bind`**：模型路径、特征/真值 Excel、**页面内联风速—功率 JSON**（预测时写临时 Excel）。
- 特征/真值 **上传、下载**；**`live=true`** 时接口内同步预测以保证与磁盘数据一致。
- 预测结果可写 **设备统计**；**中文运维总结**（大模型优先，失败规则摘要）。

**实现要点**

- 控制器 **`/wind/forecast`**；**WindForecastBridgeService** HTTP 调本地 Python。
- **路径解析**：绑定路径 → 设备目录上传文件 → **仅当** `wind.forecast.bind-device-id` **与当前 deviceId 一致** 时才允许回退 **yml 全局默认 Excel/模型**，避免未绑定设备误用全局演示数据。
- 定时任务侧需注意：**按设备** 预测须带 **deviceId**，避免全局默认文件写入错误设备的缓存。

**论文可写点**：Java + Python 异构集成；配置优先级与数据隔离；缓存与 `live` 刷新策略。

---

### 3.7 站内消息与推送去重

**功能**

- **运维表单**（`msg_type = maintenance_form`，`biz_id = form_id`）：草稿/待处理表单提醒。
- **待维护设备**（`msg_type = maintenance_device_pending`，`biz_id = device_id`）：与需维护设备列表同步。

**实现要点**

- 表 **`sys_user_message`**（`ry-vue.sql` 已含建表；仅旧库增量时用 `sql/sys_user_message.sql`）。
- **去重策略**（当前实现）：
  - **运维表单**：同一用户对同一 `form_id` **已存在任意一条记录**则不再插入；**Redis SET NX**（按 `formId`，TTL 24h）作额外防刷（可选）。
  - **待维护设备**：先 **删除** 已不在当前待维护集合中的 `biz_id` 对应消息；再对「用户 × 设备」仅当 **尚无记录** 时插入，避免定时任务每分钟 **删未读再全量插入** 导致的重复打扰。
- 前端 **消息中心** 轮询未读数；间隔可由 **`client.poll.interval.seconds`**（`sys_config`）配置。

**论文可写点**：业务幂等与 `(user_id, msg_type, biz_id)` 语义；定时任务与实时推送协同。

## 4 关键技术与数据流小结

| 技术点 | 用途 |
|--------|------|
| Spring Boot 3 + Java 21 | 后端主框架 |
| Spring Security + JWT + `@PreAuthorize` | 认证与授权 |
| MyBatis + MySQL | 持久化 |
| Spring AI + DashScope | 对话、摘要、Text-to-SQL、运维表单故障描述总结 |
| Embedding + VectorStore | RAG |
| SSE | 流式对话 |
| HTTP 客户端 | 调用 Python 预测服务 |
| Vue 2 + Element UI | 管理端 |
| Redis（可选） | 表单推送防刷、分布式缓存等 |

**核心数据流（可画时序图）**

1. 状态入库 → 规则评估 → 告警 + 状态回写。  
2. 用户提问 →（可选）向量检索 → ChatClient → 回复 / 落库。  
3. 自然语言 → SELECT → 安全执行 → 摘要 → 前端。  
4. 预测请求 → Java → Python → 结果缓存 / 写统计 → 图表与 AI 总结。  
5. 需维护设备 / 运维表单 → `sys_user_message`（去重后）→ 消息中心。

---

## 5 非功能与安全（简述）

- 业务接口需登录；风力预测等使用菜单权限标识；Text-to-SQL 限制只读。
- 模块分层清晰，设备、AI、预测、消息解耦，便于扩展。

---

## 6 结语

本系统在若依框架上实现 **设备与多维数据管理**、**规则驱动的告警与状态联动**、**大模型与 RAG 辅助问答**、**受控自然语言查库**、**运维表单与站内消息（去重）** 以及 **Java 与 Python 协同的风电预测与总结**，形成 **采集—监测—告警—智能辅助** 闭环，可支撑毕业设计的功能完整性与一定创新性。
